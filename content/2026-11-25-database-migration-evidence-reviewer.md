# 数据库迁移 review，不该只有一段 SQL 和一句“已演练”

很多迁移评审的材料，最后只剩一段 DDL、一个窗口和一句“测试过”。

但真正需要交接的是：这份差异来自哪个 schema 快照？影响了哪些读写方和回填？所谓“演练”对应哪个环境和版本？没有回退责任人时，谁能说可以继续？

我在 [AI Database Migration Evidence Reviewer](../ideas/ai-database-migration-evidence-reviewer.md) 里，把第一版范围限定为本地导入的合成或脱敏材料：

- 迁移意图、schema 摘要、影响清单、演练摘要和回退准备必须各自带来源证据；
- 输出严格分成观察事实、阻断项、待人工确认问题与人工动作；
- 环境混用、缺快照、可执行 SQL / 连接串、演练不匹配和无回退角色都会阻断；
- `recorded_not_decided` 只能表示“已记录、尚未决定”，不能被改写成“迁移完成”。

它不连接数据库、不生成或执行 SQL、不创建备份，也不提供“执行迁移”按钮。下一步应该先用 A01–A10 合成 fixture 验证结构边界，再讨论本地、显式选择文件的只读导入。

把 AI 放在数据库迁移流程里，第一项能力不该是写 SQL，而是让每个结论都能回到证据、快照和人工责任。
