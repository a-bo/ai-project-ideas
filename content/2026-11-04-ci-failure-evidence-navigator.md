# CI 失败排障，不该从“猜原因”开始

一次 CI 红灯里通常混着三种东西：真正发生的 step、被截断或过期的日志、以及人脑很想快速补上的“根因”。如果直接让 AI 总结，很容易把后两者写成第一种。

这次新增的 [AI CI Failure Evidence Navigator](../ideas/ai-ci-failure-evidence-navigator.md) 先不做自动修复或重跑，而是把输入收紧成可复查的证据包：

1. 每段 job/step 摘要都带 run ID、来源、采集时间、截断状态和摘要；
2. 报告强制分为“观察到的事实 / 待确认假设 / 人工动作”；
3. 跨 run 日志、取消、超时、缺少原始命令和截断日志都只能导向“补证”或“未知”；
4. 不读取密钥、不自动执行 rerun、不修改代码，也不向 PR 或 Issue 发消息。

MVP 的价值不是替人宣布根因，而是让下一位接手的人知道：哪些事实已经站得住、还缺什么、下一步应该由谁执行什么命令。
